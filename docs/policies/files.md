# 사진 · 파일 저장 정책

사용자가 올리는 사진 · 파일(지금은 지출 영수증 · 프로필 사진, 앞으로 바우처 · 장소 사진)을 어디에 어떻게 두는지 모은다.
**파일을 다루는 기능을 만들거나 규칙을 바꾸면 같은 PR 에서 이 문서를 고친다.** 결정이 바뀌면 지우지 말고 「바뀐 결정」 에 날짜와 함께 남긴다.

DB 표 · 권한은 [`data-model.md`](data-model.md), 저장소 선택의 근거는 [`../engineering/library-policy.md`](../engineering/library-policy.md) 결정 기록에 있다.

## 저장소

| 항목   | 지금                                      | 최종                                                   |
| ------ | ----------------------------------------- | ------------------------------------------------------ |
| 저장소 | Supabase Storage 비공개 버킷 `receipts`   | Cloudflare R2(무료 10GB, 내려받기 전송 무료) — #18 ⑫-b |
| 이유   | R2 계정 · 버킷 · 토큰 준비 전(2026-10-08) | 운영비 0원 구성. 호스팅도 Cloudflare 라 함께 둔다      |

- **화면은 저장소를 모른다.** 올리기 · 보기 · 지우기는 모두 서버 라우트(`POST /api/receipts`)가 발급한 **서명 주소**로 한다. 화면은 받은 주소로 PUT(올리기) · GET(보기)만 한다
- 저장소 코드는 서버 모듈 하나(`src/shared/api/storage/receipts.ts`)에만 둔다. R2 로 바꿀 때 이 파일과 환경 변수만 바꾼다
- DB(`expense_receipts`)에는 저장소와 상관없는 키 · 이름 · 종류 · 크기만 둔다

## 키(경로)

`{여행 id}/{uuid}.{확장자}` — 예: `ff60…/2b1c….jpg`

- 첫 칸이 여행이라 **경로만 보고 그 여행 멤버인지 가린다**(서버 라우트 · Supabase 버킷 정책 둘 다)
- 파일 이름은 사용자가 고른 이름을 쓰지 않는다(겹침 · 특수 문자 · 경로 조작). 원래 이름은 DB `name` 에 둔다
- 서버는 그 여행 폴더 밖의 키(`../` 포함)에는 주소를 발급하지 않는다(`keysInTrip`)

## 받는 파일

| 규칙      | 값                                                       | 지키는 곳                                                 |
| --------- | -------------------------------------------------------- | --------------------------------------------------------- |
| 종류      | 사진(JPG · PNG · WebP · HEIC · HEIF) · PDF               | 화면 · 서버 라우트 · DB check · 버킷 `allowed_mime_types` |
| 크기      | 파일당 10MB                                              | 화면 · 서버 라우트 · DB check · 버킷 `file_size_limit`    |
| 장수      | **지출당 3장**(2026-10-08)                               | 화면 · DB 트리거(`expense_receipts_limit`, 0042)          |
| 필수 여부 | 선택 — 없어도 저장된다. 올리는 중에만 「완료」 를 막는다 | 화면                                                      |

규칙 값은 `src/entities/expense/lib/receipt-rules.ts` 한 곳에서 화면 · 서버가 함께 쓴다. 바꾸면 DB(마이그레이션) · 버킷 설정도 같은 값으로 맞춘다.

## 압축

저장 비용과 불러오는 속도를 함께 줄이려고 **화면에서 줄인 뒤 올린다**(`src/shared/lib/compress-image.ts`, 새 라이브러리 없이 브라우저 canvas).

- 사진: 긴 변 **2000px**, JPEG 품질 **82%**. 휴대폰 사진(1~4MB)이 보통 200~400KB 가 된다
  - 일반 영수증(길이 15~20cm)은 인치당 250~340 화소로 작은 글씨까지 읽힌다. 50cm 넘는 긴 영수증을 한 장에 담으면 흐려질 수 있다 — 실제 사진으로 확인해 부족하면 2560~3000px 로 올린다
  - 투명한 PNG 는 흰 바탕을 깔고 JPEG 으로 바꾼다
  - 줄인 결과가 원본보다 크면 원본을 올린다
  - 브라우저가 못 읽는 사진(예: Chrome 의 HEIC)은 원본 그대로 올린다
- PDF: 줄이지 않는다. 글자로 된 PDF 는 쪽당 50~300KB 라 10MB 면 수십 쪽 이상, 스캔 PDF 는 쪽당 0.5~2MB 라 5~20쪽 정도다

## 올리기 · 붙이기 · 지우기

1. 파일을 **고르는 순간** 줄여서 올린다(저장 전). 올리는 동안 「완료」 는 꺼진다
2. 지출을 **저장할 때** `expense_receipts` 줄을 붙인다
   - 새 지출: 지출 → 몫 → 영수증 줄. 영수증 줄을 붙이지 못하면 지출도 되돌린다(다시 저장해도 두 번 생기지 않게)
   - 수정: 새로 올린 것은 붙이고, 뺀 것은 줄을 지운 뒤 파일도 지운다. 저장하지 않고 닫으면 붙어 있던 것은 그대로다
3. 지출을 지우면 줄은 함께 지워지고(cascade), 그 파일은 지운 뒤 저장소에서 지운다

**붙지 못한 파일**(저장하지 않고 닫은 업로드 · 파일 지우기 실패 · 여행 삭제)은 정해진 주기로 정리한다 — #155(R2 로 바꾼 뒤).

## 보기

- 서버가 발급한 **읽기 주소는 1시간** 유효하다. 기기 캐시(IndexedDB)에 저장하지 않는다(`shouldPersistQuery`)
- 묶음(모바일 상세 96 · PC 패널 56)을 누르면 새 창에서 원본을 연다. 영수증 · 바우처 뷰어를 만들면 바꾼다
- 일행이 붙인 영수증은 실시간으로 보인다(`expense_receipts` 발행)

## 누가 올리나

- **그 여행 멤버만** — 서버 라우트(로그인 · 그 여행이 보이는지)와 저장소 정책(경로 첫 칸 여행의 멤버) 두 층에서 막는다
- **익명(둘러보기) 계정도 자기 여행에는 올릴 수 있다**(2026-10-08) — 둘러보기에서 영수증 기능을 써 볼 수 있게.
  남의 여행에는 들어갈 수 없어 흔적을 남기지 않는다(AGENTS.md 「인증 경계」 기준)
- 3장 제한은 **지출에 붙일 때**(DB 트리거)만 걸린다. 올리기 자체에는 장수 · 횟수 제한이 없어서, 붙이지 않을 파일을 계속 올리면 저장 용량을 쓸 수 있다.
  익명은 **계정 전체 3장**까지로 막기로 했다(2026-10-08, #157 — 올리기 주소 발급 횟수를 장부 표로 센다). 익명 계정과 그 데이터는 매일 배치로 지운다(#158)

## 프로필 사진(#94)

영수증과 다른 점만 적는다.

| 항목     | 값                                                                                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 저장소   | Supabase Storage **공개** 버킷 `avatars`(0043) — 영수증과 함께 R2 로 옮긴다                                                                                                                                                     |
| 키       | `{사용자 id}/{uuid}.{확장자}` — 첫 칸이 사용자라 자기 폴더만 올리고 지운다(라우트 · 버킷 정책 둘 다)                                                                                                                            |
| 보기     | 공개 주소를 `profiles.avatar_url` 에 그대로 둔다. 아바타는 화면 곳곳에 그려져 서명 주소를 쓰지 않는다                                                                                                                           |
| 종류     | JPG · PNG · WebP(줄인 뒤 기준). 브라우저가 못 읽는 사진(Chrome 의 HEIC)은 받지 않고 안내한다                                                                                                                                    |
| 크기     | 화면에서 긴 변 **512px** 로 줄인다(아바타 최대 72 의 3배를 넘는다). 한 장 2MB 까지(라우트 · 버킷)                                                                                                                               |
| 누가     | 로그인한 사람, **둘러보기(익명)는 막는다**(2026-10-09) — 사진을 볼 일행이 없고 매일 지워지는 계정이다                                                                                                                           |
| 바꾸기   | 고르면 미리 보이고, 「저장」 때 올린 뒤 프로필에 주소를 적는다. 그다음 저장 직전 DB 의 앞 사진 파일을 지운다(실패해도 저장은 끝난 것 — 남는 파일). 주소를 적지 못하면 방금 올린 파일을 지운다. 사진을 그대로 두면 이름만 적는다 |
| 기본으로 | 「기본 이미지로」 = 가입 때 받은 구글 사진(`default_avatar_url`), 없으면 이니셜. 올린 사진 파일은 지운다                                                                                                                        |

**함정**: Storage 의 `remove` 는 지울 파일을 RLS 로 먼저 찾는다. 공개 버킷이라도 읽기(select) 정책이 없으면 0건을 찾고 **오류 없이** 끝난다 — 그래서 자기 폴더 읽기 정책을 둔다(0044). 새 버킷을 만들 때 지우기가 있으면 읽기 정책도 함께 둔다.

규칙 값은 `src/entities/session/lib/avatar-rules.ts` 한 곳에서 화면 · 서버가 함께 쓴다. 저장소 코드는 `src/shared/api/storage/avatars.ts` 에만 둔다.
