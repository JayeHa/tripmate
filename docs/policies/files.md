# 사진 · 파일 저장 정책

사용자가 올리는 사진 · 파일(지금은 지출 영수증 · 프로필 사진, 앞으로 바우처 · 장소 사진)을 어디에 어떻게 두는지 모은다.
**파일을 다루는 기능을 만들거나 규칙을 바꾸면 같은 PR 에서 이 문서를 고친다.** 결정이 바뀌면 지우지 말고 「바뀐 결정」 에 날짜와 함께 남긴다.

DB 표 · 권한은 [`data-model.md`](data-model.md), 저장소 선택의 근거는 [`../engineering/library-policy.md`](../engineering/library-policy.md) 결정 기록에 있다.

## 저장소

| 항목   | 지금                                      | 최종                                                   |
| ------ | ----------------------------------------- | ------------------------------------------------------ |
| 저장소 | Supabase Storage 비공개 버킷 `receipts`   | Cloudflare R2(무료 10GB, 내려받기 전송 무료) — #18 ⑫-b |
| 이유   | R2 계정 · 버킷 · 토큰 준비 전(2026-10-08) | 운영비 0원 구성. 호스팅도 Cloudflare 라 함께 둔다      |

- **화면은 저장소를 모른다.** 올리기 · 보기 · 지우기는 모두 서버 라우트(`POST /api/receipts`)가 발급한 **서명 주소**로 한다. 화면은 받은 주소로 PUT(올리기) · GET(보기)만 한다
- 저장소 코드는 서버 모듈 하나(`src/shared/api/storage/receipts.ts`)에만 둔다. R2 로 바꿀 때 이 파일과 환경 변수만 바꾼다
- DB(`expense_receipts`)에는 저장소와 상관없는 키 · 이름 · 종류 · 크기만 둔다

## 키(경로)

`{여행 id}/{uuid}.{확장자}` — 예: `ff60…/2b1c….jpg`

- 첫 칸이 여행이라 **경로만 보고 그 여행 멤버인지 가린다**(서버 라우트 · Supabase 버킷 정책 둘 다)
- 파일 이름은 사용자가 고른 이름을 쓰지 않는다(겹침 · 특수 문자 · 경로 조작). 원래 이름은 DB `name` 에 둔다
- 서버는 그 여행 폴더 밖의 키(`../` 포함)에는 주소를 발급하지 않는다(`keysInTrip`)

## 받는 파일

| 규칙      | 값                                                       | 지키는 곳                                                 |
| --------- | -------------------------------------------------------- | --------------------------------------------------------- |
| 종류      | 사진(JPG · PNG · WebP · HEIC · HEIF) · PDF               | 화면 · 서버 라우트 · DB check · 버킷 `allowed_mime_types` |
| 크기      | 파일당 10MB                                              | 화면 · 서버 라우트 · DB check · 버킷 `file_size_limit`    |
| 장수      | **지출당 3장**(2026-10-08)                               | 화면 · DB 트리거(`expense_receipts_limit`, 0042)          |
| 필수 여부 | 선택 — 없어도 저장된다. 올리는 중에만 「완료」 를 막는다 | 화면                                                      |

규칙 값은 `src/entities/expense/lib/receipt-rules.ts` 한 곳에서 화면 · 서버가 함께 쓴다. 바꾸면 DB(마이그레이션) · 버킷 설정도 같은 값으로 맞춘다.

## 압축

저장 비용과 불러오는 속도를 함께 줄이려고 **화면에서 줄인 뒤 올린다**(`src/shared/lib/compress-image.ts`, 새 라이브러리 없이 브라우저 canvas).

- 사진: 긴 변 **2000px**, JPEG 품질 **82%**. 휴대폰 사진(1~4MB)이 보통 200~400KB 가 된다
  - 일반 영수증(길이 15~20cm)은 인치당 250~340 화소로 작은 글씨까지 읽힌다. 50cm 넘는 긴 영수증을 한 장에 담으면 흐려질 수 있다 — 실제 사진으로 확인해 부족하면 2560~3000px 로 올린다
  - 투명한 PNG 는 흰 바탕을 깔고 JPEG 으로 바꾼다
  - 줄인 결과가 원본보다 크면 원본을 올린다
  - 브라우저가 못 읽는 사진(예: Chrome 의 HEIC)은 원본 그대로 올린다
- PDF: 줄이지 않는다. 글자로 된 PDF 는 쪽당 50~300KB 라 10MB 면 수십 쪽 이상, 스캔 PDF 는 쪽당 0.5~2MB 라 5~20쪽 정도다

## 올리기 · 붙이기 · 지우기

1. 파일을 **고르는 순간** 줄여서 올린다(저장 전). 올리는 동안 「완료」 는 꺼진다
2. 지출을 **저장할 때** `expense_receipts` 줄을 붙인다
   - 새 지출: 지출 → 몫 → 영수증 줄. 영수증 줄을 붙이지 못하면 지출도 되돌린다(다시 저장해도 두 번 생기지 않게)
   - 수정: 새로 올린 것은 붙이고, 뺀 것은 줄을 지운 뒤 파일도 지운다. 저장하지 않고 닫으면 붙어 있던 것은 그대로다
3. 지출을 지우면 줄은 함께 지워지고(cascade), 그 파일은 지운 뒤 저장소에서 지운다
   - 숙소를 지우면 결제 비용과 영수증 줄이 cascade 로 지워진다. 화면이 지우기 전에 그 키를 읽어 두고, 지운 뒤 파일을 지운다
4. 새 숙소 폼의 결제(아직 붙일 비용이 없다)는 올린 파일의 키를 초안으로 들고 있다가, 숙소를 저장한 뒤 비용을 만들며 붙인다. 초안을 고치며 뺀 파일 · 초안을 지운 파일 · 결제 저장에 실패한 파일은 바로 지운다. 숙소를 저장하지 않고 닫으면 붙지 못한 파일로 남는다

**붙지 못한 파일**(저장하지 않고 닫은 업로드 · 파일 지우기 실패 · 여행 삭제)은 정해진 주기로 정리한다 — #155(R2 로 바꾼 뒤).

## 보기

- 서버가 발급한 **읽기 주소는 1시간** 유효하다. 기기 캐시(IndexedDB)에 저장하지 않는다(`shouldPersistQuery`)
- 묶음(모바일 상세 96 · PC 패널 56)을 누르면 새 창에서 원본을 연다. 영수증 · 바우처 뷰어를 만들면 바꾼다
- 일행이 붙인 영수증은 실시간으로 보인다(`expense_receipts` 발행)

## 누가 올리나

- **그 여행 멤버만** — 서버 라우트(로그인 · 그 여행이 보이는지)와 저장소 정책(경로 첫 칸 여행의 멤버) 두 층에서 막는다
- **익명(둘러보기) 계정도 자기 여행에는 올릴 수 있다**(2026-10-08) — 둘러보기에서 영수증 기능을 써 볼 수 있게.
  남의 여행에는 들어갈 수 없어 흔적을 남기지 않는다(AGENTS.md 「인증 경계」 기준)
- 3장 제한은 **지출에 붙일 때**(DB 트리거)만 걸린다. 올리기 자체에는 장수 · 횟수 제한이 없어서, 붙이지 않을 파일을 계속 올리면 저장 용량을 쓸 수 있다.
  익명은 **계정 전체 3장**까지로 막기로 했다(2026-10-08, #157 — 올리기 주소 발급 횟수를 장부 표로 센다). 익명 계정과 그 데이터는 매일 배치로 지운다(#158)

## 프로필 사진(#94)

영수증과 다른 점만 적는다.

| 항목     | 값                                                                                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 저장소   | Supabase Storage **공개** 버킷 `avatars`(0043) — 영수증과 함께 R2 로 옮긴다                                                                                                                                                     |
| 키       | `{사용자 id}/{uuid}.{확장자}` — 첫 칸이 사용자라 자기 폴더만 올리고 지운다(라우트 · 버킷 정책 둘 다)                                                                                                                            |
| 보기     | 공개 주소를 `profiles.avatar_url` 에 그대로 둔다. 아바타는 화면 곳곳에 그려져 서명 주소를 쓰지 않는다                                                                                                                           |
| 종류     | JPG · PNG · WebP(줄인 뒤 기준). 브라우저가 못 읽는 사진(Chrome 의 HEIC)은 받지 않고 안내한다                                                                                                                                    |
| 크기     | 화면에서 긴 변 **512px** 로 줄인다(아바타 최대 72 의 3배를 넘는다). 한 장 2MB 까지(라우트 · 버킷)                                                                                                                               |
| 누가     | 로그인한 사람, **둘러보기(익명)는 막는다**(2026-10-09) — 사진을 볼 일행이 없고 매일 지워지는 계정이다. 올리기만 막는다 — `avatar_url` 칸은 본인이 고칠 수 있어 DB 검사는 #181                                                   |
| 바꾸기   | 고르면 미리 보이고, 「저장」 때 올린 뒤 프로필에 주소를 적는다. 그다음 저장 직전 DB 의 앞 사진 파일을 지운다(실패해도 저장은 끝난 것 — 남는 파일). 주소를 적지 못하면 방금 올린 파일을 지운다. 사진을 그대로 두면 이름만 적는다 |
| 기본으로 | 「기본 이미지로」 = 가입 때 받은 구글 사진(`default_avatar_url`), 없으면 이니셜. 올린 사진 파일은 지운다                                                                                                                        |

**함정**: Storage 의 `remove` 는 지울 파일을 RLS 로 먼저 찾는다. 공개 버킷이라도 읽기(select) 정책이 없으면 0건을 찾고 **오류 없이** 끝난다 — 그래서 자기 폴더 읽기 정책을 둔다(0044). 새 버킷을 만들 때 지우기가 있으면 읽기 정책도 함께 둔다.

규칙 값은 `src/entities/session/lib/avatar-rules.ts` 한 곳에서 화면 · 서버가 함께 쓴다. 저장소 코드는 `src/shared/api/storage/avatars.ts` 에만 둔다.

## 바우처(#16)

노트 › 바우처. 영수증과 다른 점만 적는다. 화면 규칙(폼 · 목록 · 뷰어)은 디자인 핸드오프 `notes - Notes Flow` · `shared - Voucher Viewer` 를 따르고, 시안과 다르게 정한 것은 [`../design/deviations.md`](../design/deviations.md).

| 항목        | 값                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 파일 수     | 바우처 하나에 **원본 1개**(사진 또는 PDF, 교체만). 파일 없이 번호만 있는 바우처도 된다(시안)                                                                                                                                                                                                                                                                                                                                                      |
| 종류 · 크기 | 영수증과 같은 종류(JPG · PNG · WebP · HEIC · HEIF · PDF), **파일당 20MB**(시안 17g)                                                                                                                                                                                                                                                                                                                                                               |
| 압축        | **하지 않는다**(2026-10-15 사용자 결정) — QR · 바코드 · 작은 글씨가 많고 「원본 저장」(P35)으로 그 파일을 다시 받는다. 브라우저가 못 읽는 사진(Chrome 의 HEIC)도 원본 그대로 올린다                                                                                                                                                                                                                                                               |
| PDF 그림    | PDF 는 **올릴 때** 올리는 사람의 브라우저가 `pdfjs-dist` 로 현장용 페이지(폼의 「현장용 페이지」, 기본 `1`)와 썸네일을 그림으로 만들어 원본과 함께 저장한다. 뷰어 · 목록 · 홈은 이 그림만 보인다(2026-10-15 사용자 결정, [`../engineering/library-policy.md`](../engineering/library-policy.md) 결정 기록). 현장용 페이지를 고치면 원본을 다시 받아 그린다. 그리지 못한 브라우저에서는 원본만 저장하고 뷰어는 「PDF 열기」                        |
| 연결        | 바우처 하나는 일정 카드 · 항공편 · 숙소 중 **하나**에 붙거나 붙지 않는다(기타). 체크리스트처럼 여러 개가 아니다(2026-10-15 사용자 결정, 시안대로)                                                                                                                                                                                                                                                                                                 |
| 바로 올리기 | 일정 · 항공편 · 숙소 상세의 「+ 바우처」 는 폼 없이 **바로 만든다** — 제목은 파일 이름(확장자 뺀 것), 연결은 그 일정(항공편 · 숙소 카드면 그 항공편 · 숙소). 주인 모두 · PDF 는 1쪽을 그림으로. 줄 저장까지 실패하면 올린 원본 · 그림을 지운다. 번호 · 메모는 나중에 수정에서(2026-10-15 사용자 결정, 시안대로)                                                                                                                                   |
| 다운로드    | 원본을 그대로 받는다(서명 주소에서 받아 파일로 만든다 — 주소를 그대로 열면 키 이름으로 저장된다). 파일 이름 = 제목 + 원본 확장자(원본 이름에 없으면 종류에서, 쓸 수 없는 글자는 「_」). 일행이 올린 것도 누구나. 모바일(손가락으로 쓰는 기기)은 `navigator.share({ files })` 먼저, 안 되면(iOS 에서 받는 사이 사용자 동작 인정 시간이 지남 등) 다운로드. PC 는 바로 다운로드. 토스트 「{파일명} 저장했어요」(P35), 공유 시트를 닫으면 토스트 없음 |
| 지우기      | 바우처를 지우면(뷰어 ⋯ → 삭제) 줄을 지운 뒤 원본 · 그림 · 썸네일 가운데 **다른 바우처가 쓰지 않는 키만** 저장소에서 지운다(「키 겹침」). 연결 대상을 지우면 연결만 풀린다(영수증 · 체크리스트와 같은 cascade 규칙)                                                                                                                                                                                                                                |
| 누가        | 영수증과 같다 — 그 여행 멤버, 익명도 자기 여행에는 된다                                                                                                                                                                                                                                                                                                                                                                                           |

저장소는 영수증과 같은 구조로 따로 둔다 — 비공개 버킷 `vouchers`(0059, 파일당 20MB 라 영수증 버킷과 크기 제한이 다르다) · 라우트 `POST /api/vouchers`(올리기 · 보기 · 지우기, 원본과 그림이 모두 이 길) · 서버 모듈 `src/shared/api/storage/vouchers.ts`. 키 규칙(`{여행 id}/{uuid}.{확장자}`)과 읽기 주소 1시간 · 기기에 저장하지 않음도 영수증과 같다. 규칙 값은 `src/entities/voucher/lib/voucher-rules.ts`. 현장용 페이지 그림은 **5장까지**(DB `page_keys`).

**키 겹침**: DB 는 원본 키(`file_key`)만 겹치지 않게 막는다. 그림 키(`thumb_key` · `page_keys`)는 다른 줄과 겹쳐도 막지 않고 멤버 누구나 줄을 고칠 수 있어, 한 줄의 키를 다른 줄 키로 바꾼 뒤 지우면 그 줄의 그림까지 지워진다. 그래서 바우처를 지우거나 파일을 바꿀 때는 **다른 줄이 쓰지 않는 키만** 저장소에서 지운다(지우기 · 교체를 만드는 PR). 키는 그 여행 폴더 안으로 막혀 있어(`vouchers_keys_chk`) 영향은 같은 여행 안에 그친다.

**그림**(①-b, `src/features/voucher/lib`):

- 현장용 페이지 = PNG, 폭 **1600px**(휴대폰 전체 화면 390pt × 3 보다 넉넉해 QR · 바코드가 또렷하다), 아주 긴 페이지는 긴 변 4096px 에서 멈춘다(iOS Safari 캔버스 한도). 적은 순서대로(「2, 1」 이면 2쪽 먼저), 문서 쪽수를 넘는 번호는 뺀다
- 썸네일 = JPEG, 긴 변 **400px**(목록 48 · 상세 132 칸). PDF 는 첫 현장용 페이지 그림으로, 사진은 원본으로 만든다. 브라우저가 못 읽는 사진(Chrome 의 HEIC)은 썸네일 없이(목록은 아이콘)
- 그리는 때 = **저장할 때**. 원본은 고르자마자 올리고, 그림은 저장 버튼을 누른 뒤 만들어 올린 다음 줄을 저장한다(현장용 페이지를 저장 직전까지 고칠 수 있어서). 원본은 그대로인데 현장용 페이지만 바꾸면 원본을 다시 받아 그린다
- pdf.js 는 그릴 때 `requestAnimationFrame` 으로 쉬어 가서, 저장 중에 앱 · 탭을 벗어나면 그리기가 멈췄다가 돌아오면 이어진다

**저장 순서와 파일 정리**: ① 그림 만들기 · 올리기 → ② 줄 저장(수정은 바뀐 칸만) → ③ 바꾼 옛 원본 · 그림을 지운다(다른 줄이 쓰지 않는 키만). ②가 실패하면 ①에서 올린 그림을 지운다. 고른 새 원본은 저장하지 않고 창을 닫거나 다른 파일로 바꾸면 바로 지운다(올리는 중이면 끝난 뒤). 저장을 누른 뒤에는 저장 쪽이 맡아, 저장 중에 창이 사라져도 지우지 않고 저장이 실패할 때만 지운다. 새로고침 · 앱 종료로 창이 사라지면 남는다 — 붙지 못한 파일 정리(#155)가 맡는다.

## 쇼핑 참고 사진(#16)

노트 › 쇼핑 항목의 참고 사진(인터넷에서 본 포장 · 제품 캡처). 영수증 · 바우처와 다른 점만 적는다. 화면 규칙은 디자인 핸드오프 `notes - Notes Flow` 를 따르고, 시안과 다르게 정한 것은 [`../design/deviations.md`](../design/deviations.md).

| 항목        | 값                                                                                                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 장수        | 항목 하나에 **한 장**(교체 · 삭제). 준비물 · 쇼핑이 같은 테이블이라 칸은 둘 다 있지만 화면은 쇼핑에서만 쓴다                                                                       |
| 압축        | 화면에서 **긴 변 1600 JPEG**(품질 82%)으로 줄이고, 목록 썸네일(**긴 변 192**)을 따로 만든다(2026-10-20 사용자 결정, `compressImage`). 목록에 사진이 많아도 썸네일만 받는다         |
| 종류 · 크기 | 줄인 뒤의 JPG · PNG · WebP(줄인 것이 원본보다 크면 원본), 한 장 **5MB** 까지. 브라우저가 못 읽는 사진(Chrome 의 HEIC)은 줄이지 못해 받지 않고 「이 사진은 열 수 없어요」 로 알린다 |
| 올리는 곳   | 줄 오른쪽 48 점선 칸(고르면 **바로** 붙인다) · 상세 시트의 큰 칸(**저장할 때** 붙인다) · 전체 화면의 「교체」(바로)                                                                |
| 지우기      | 전체 화면 「삭제」(확인 창) · 시트의 「사진 지우기」 뒤 저장 · 항목 삭제 · 그룹 삭제(지우기 전에 그 그룹 사진 키를 읽어 둔다) · 교체(앞 사진). 줄을 바꾼 뒤 파일을 지운다          |
| 누가        | 영수증과 같다 — 그 여행 멤버, 익명도 자기 여행에는 된다                                                                                                                            |

저장소는 바우처와 같은 구조로 따로 둔다 — 비공개 버킷 `pack-photos`(0062, 줄인 사진만 받아 5MB · 사진 종류만) · 라우트 `POST /api/pack-photos`(올리기 · 보기 · 지우기) · 서버 모듈 `src/shared/api/storage/pack-photos.ts`. 키 규칙(`{여행 id}/{uuid}.{확장자}`)과 읽기 주소 1시간 · 기기에 저장하지 않음도 같다. 규칙 값은 `src/entities/pack/lib/photo-rules.ts`. 두 키 모두 DB 에서 줄마다 겹치지 않아(unique) 바우처의 「키 겹침」 확인은 하지 않는다.

**시트의 사진**: 고르면 바로 올리고, 「저장」 때 항목에 붙인다. 시트가 올린 사진은 다른 사진으로 바꾸거나 · 「사진 지우기」 · 저장하지 않고 닫으면 바로 지운다(올리는 중이면 끝난 뒤). 닫힌 창은 DOM 에 남아 언마운트를 기다리지 않고 닫히는 순간 지운다. 저장을 누른 뒤에는 저장 쪽이 맡아, 저장하면 앞 사진을 · 실패하면 새 사진을 지운다. 그사이 일행이 같은 항목의 사진을 바꿨으면 그 사진은 남을 수 있다(#155 가 정리). 새로고침 · 앱 종료로 사라진 업로드도 같다.
