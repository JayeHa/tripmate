# 오프라인 정책

여행지에서 통신이 끊겨도 앱을 열고(보기) 현장 동작을 하게(편집) 하는 규칙을 모은다(#20).
**오프라인 동작을 바꾸면 같은 PR 에서 이 문서를 고친다.** 결정이 바뀌면 지우지 말고 「바뀐 결정」 에 날짜와 함께 남긴다.

화면 · 사진을 기기에 남기는 규칙(서비스 워커)은 [`files.md`](files.md) 「오프라인」 에 있다.

## 보기

- 화면: 서비스 워커가 연 화면을 7일 남긴다(배포마다 따로). 안 가 본 화면은 「오프라인이에요」 대체 페이지
- 데이터: TanStack 캐시를 IndexedDB(`tripmate-query-cache`)에 7일 남긴다. 저장(뮤테이션)은 여기에 넣지 않는다(#195)
- 화면 맨 위 오프라인 띠(`widgets/connection-status`) — 「오프라인이에요 · 저장해 둔 일정과 바우처는 볼 수 있어요」

## 편집 — 오프라인 대기열

**현장 동작만** 오프라인에서 된다(2026-10-23 사용자 결정). 나머지 저장은 오프라인이면 막는다 — 「오프라인이에요. 연결되면 다시 해 주세요」(`OfflineError`).

| 동작                    | 대기열 | 키                             | PR  |
| ----------------------- | ------ | ------------------------------ | --- |
| 체크리스트 체크(상태)   | ✅     | `["sync", "checklist-status"]` | ②-a |
| 준비물 · 쇼핑 챙김      | ✅     | `["sync", "pack-checked"]`     | ②-a |
| 메모 추가 · 수정 · 삭제 | 다음   |                                | ②-b |
| 비용 추가(영수증 제외)  | 다음   |                                | ②-b |
| 그 밖의 모든 저장       | ❌     | 오프라인이면 막는다            |     |

- 대기열 저장은 오프라인이면 멈췄다가(TanStack `networkMode: "online"`) 연결되면 올라간다. 대기열은 한 줄(`scope`)이라 같은 항목을 여러 번 바꿔도 누른 순서대로 올라간다
- 화면은 누르는 순간 바뀐다(낙관적). 지워졌거나 권한이 없어 실패하면 다시 해 보지 않고 그 항목만 되돌린 뒤 대기열에서 뺀다(`dropDeadEndFailures` — 다시 해도 같아서). 서버에 닿지 못해 실패하면(3번 다시 해 본 뒤, `retrySync`) 화면은 그대로 두고 「저장 실패 · 다시 시도」 로 남긴다
- 앱을 닫거나 새로고침해도 남는다 — 대기열은 TanStack 캐시와 따로 IndexedDB(`tripmate-sync` › `outbox`)에 저장 하나마다 한 줄로 쓰고, 줄마다 주인 탭을 적는다.
  TanStack 의 캐시 저장은 탭마다 캐시 전체를 한 칸에 통째로 써서, 같은 앱이 열린 다른 탭이 나중에 쓰면 이 탭의 대기열이 사라졌다(②-a 확인 중 발견)
- 탭은 살아 있는 동안 잠금(Web Locks `tm-sync-tab-{id}`)을 쥔다. 앱이 시작할 때 주인 탭이 닫힌 줄만 누른 순서대로 다시 올린다(`tm-sync-claim` 잠금으로 한 탭씩) — 살아 있는 다른 탭의 대기열은 건드리지 않는다
- 저장 함수는 키마다 `queryClient.setMutationDefaults` 로 앱이 시작할 때 등록한다(`registerChecklistSync` · `registerPackSync`) — 기기에서 되살린 저장에는 함수가 없어서
- 끝난 저장의 줄은 지운다. 서버에 닿지 못해 실패한 줄만 남긴다 — 그 탭에서는 「다시 시도」, 닫히면 다음에 열 때 다시 올린다

## 일행과 같은 항목을 고쳤을 때

**나중 수정 우선 + 알림**(시안대로, 2026-10-23 사용자 결정).

- 누를 때 본 항목의 버전(`updated_at`)을 함께 보낸다. 올릴 때 그 버전이면 그대로 고치고, 그사이 일행이 고쳤으면 내 것으로 덮고 「일행이 먼저 고친 항목을 내 수정으로 바꿨어요」(`updateLatestWins`)
- 덮는 것은 내가 바꾼 칸만이다(체크는 상태 · 챙김 칸) — 일행이 고친 다른 칸(제목 등)은 그대로 남는다
- 같은 항목을 오프라인에서 두 번 바꾸면 두 번째는 내가 만든 버전과 비교한다(이 탭에서만 기억). 새로고침 뒤에 이어 올린 것은 기억이 없어 내 수정을 일행 것으로 잘못 알릴 수 있다
- 그사이 지워졌으면 그 항목만 되돌린다

## 동기화 칩

`widgets/connection-status`. 대기열에 상태가 있을 때만 보인다 — 평소 온라인 저장마다 깜빡이지 않게.

| 칩                    | 언제                                                                       |
| --------------------- | -------------------------------------------------------------------------- |
| 변경 N건 대기         | 오프라인이라 멈춘 대기열 저장이 있다                                       |
| 저장 중…              | 기다리던 변경을 올리는 중(오프라인에서 쌓였거나 되살아난 것)               |
| 모두 저장됨           | 기다리던 변경이 다 올라간 순간, 2초                                        |
| 저장 실패 · 다시 시도 | 서버에 닿지 못해 실패한 대기열 저장이 있다. 누르면 같은 값으로 다시 올린다 |

- 오프라인이면 띠 오른쪽, 온라인이면 오른쪽 위 헤더 바로 아래에 뜬다. 일행의 수정을 덮었다는 알림은 칩 아래에 잠깐(화면 토스트와 겹치지 않게 위)

## 확인할 때

- 자동화 탭은 오프라인으로 바꿀 수 없다 — `navigator.onLine` 을 바꾸고 `offline` · `online` 이벤트를 보내 흉내 낸다
- TanStack 은 탭이 보이지 않으면(자동화 탭은 늘 백그라운드) 멈춘 저장을 잇지 않는다 — `document.visibilityState` 를 `visible` 로 바꾸고 `window` 에 `visibilitychange` 를 보낸다
- 같은 앱이 열린 다른 탭이 있으면 캐시 저장(`tripmate-query-cache`)을 덮는다 — 대기열은 따로 있어 상관없지만, 캐시를 볼 때는 다른 탭을 닫는다

## 바뀐 결정

- 2026-10-23 · 오프라인 편집은 현장 동작만 대기열(체크 · 메모 · 비용 추가), 충돌은 나중 수정 우선 + 알림, 칩은 띠 안 · 오른쪽 위(#20 ②)
