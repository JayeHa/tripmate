# 오프라인 정책

여행지에서 통신이 끊겨도 앱을 열고(보기) 현장 동작을 하게(편집) 하는 규칙을 모은다(#20).
**오프라인 동작을 바꾸면 같은 PR 에서 이 문서를 고친다.** 결정이 바뀌면 지우지 말고 「바뀐 결정」 에 날짜와 함께 남긴다.

화면 · 사진을 기기에 남기는 규칙(서비스 워커)은 [`files.md`](files.md) 「오프라인」 에 있다.

## 보기

- 화면: 서비스 워커가 연 화면을 7일 남긴다(배포마다 따로). 안 가 본 화면은 「오프라인이에요」 대체 페이지 — 「오프라인용으로 받기」 로 받은 여행은 안 가 본 화면도 열린다(아래)
- 데이터: TanStack 캐시를 IndexedDB(`tripmate-query-cache`)에 61일 남긴다(받은 여행의 가장 긴 보관 60일 + 하루). 저장(뮤테이션)은 여기에 넣지 않는다(#195)
- 화면 맨 위 오프라인 띠(`widgets/connection-status`) — 「오프라인이에요 · 받아 둔 여행은 그대로 열 수 있어요」

## 오프라인용으로 받기

내 여행의 ⋯ 메뉴(모바일 시트 · PC 드롭다운)에서 여행 하나를 통째로 받는다(#20 ③, 시안 62a–62o). 자동 저장(본 것만)은 그대로 두고, 이 버튼은 안 열어 본 것까지 전부 받는다.

- 받는 것: 그 여행의 데이터 전부(쿼리 18개를 새로 읽어 캐시에 — 기기에 남는다) → 화면(탭 화면 · 가계부 하위 · 비용 상세) → 바우처 그림 · 썸네일 · 쇼핑 사진. 받지 않는 것: 지도(약관 · 오프라인이면 반쯤 깨진다) · 수정 화면 · 바우처 PDF 원본
- **페이지가 받는다**(`features/trip/offline-download`) — 데이터는 앱 화면의 캐시라 서비스 워커가 채울 수 없다. 화면 · 사진은 서비스 워커에 메시지(`offline-save`)로 맡겨 여행마다 따로 둔 칸(`offline-pages:{여행}:{빌드}` · `offline-files:{여행}`)에 넣는다 — 자동 저장 칸(64개 · 7일 · 200장)에서 밀려나거나 먼저 지워지지 않게. 자동 저장 칸에 없으면 이 칸에서 찾는다
- 「창을 닫아도 계속 받아요」 는 앱이 열려 있는 동안이다. 도중에 앱을 닫으면 다음에 열 때 「N개를 받지 못했어요」(남은 것을 못 받은 것으로 센다), 「다시 받기」 는 전부
- 한 번에 4개씩. 오프라인이 되면 남은 것은 시도하지 않고 못 받은 것으로 센다. 「다시 받기」(일부 실패)는 못 받은 것만
- 보관: **받은 날부터 7일과 여행 끝 다음 날 중 늦은 날까지**, 길어도 받은 날부터 60일(2026-10-23 사용자 결정). 앱이 시작할 때 기한이 지난 여행의 기록 · 칸을 지운다(`pruneOfflineTrips`)
- 데이터 모양이 바뀐 배포(`QUERY_CACHE_BUSTER`)는 기기의 데이터 캐시를 통째로 버린다 — 받은 여행도 함께. 캐시를 되살린 뒤 받은 여행이 캐시에 없으면 온라인이면 데이터만 조용히 다시 읽고, 오프라인이거나 읽지 못하면 「1개를 받지 못했어요」 로 바꿔 「다시 받기」 로 이끈다(`checkSavedTripData`)
- 새 버전이 켜지면 받은 여행의 화면을 새 배포로 다시 받고 옛 칸을 지운다(`carryTripPages`) — 옛 화면은 이제 없는 JS · CSS 를 가리킨다. 사진 칸은 배포와 상관없다
- 받은 기록은 기기별 저장값 `tm-offline-saved`(상태 · 받은 수 / 전체 · 못 받은 것 · 받은 때 · 보관 기한). 로그아웃하면 칸과 함께 지운다
- 메뉴 힌트: 받은 적 없음 = 없음 · 「받는 중」 · 「10.23 받음」 · 오프라인이면 흐리게 「연결되면」(누르면 창 없이 토스트). 창을 닫은 뒤 끝나면 내 여행 화면에 토스트(실패면 「다시 받기」)

## 편집 — 오프라인 대기열

**현장 동작만** 오프라인에서 된다(2026-10-23 사용자 결정). 나머지 저장은 오프라인이면 막는다 — 「오프라인이에요. 연결되면 다시 해 주세요」(`OfflineError`).

| 동작                                                         | 대기열 | 키                                                          | PR  |
| ------------------------------------------------------------ | ------ | ----------------------------------------------------------- | --- |
| 체크리스트 체크(상태)                                        | ✅     | `["sync", "checklist-status"]`                              | ②-a |
| 준비물 · 쇼핑 챙김                                           | ✅     | `["sync", "pack-checked"]`                                  | ②-a |
| 일정 메모 추가 · 수정 · 삭제                                 | ✅     | `["sync", "memo", "create" \| "update" \| "delete"]`        | ②-b |
| 비용 추가(영수증 없는 보통 비용)                             | ✅     | `["sync", "expense-create"]`                                | ②-b |
| 영수증 있는 비용 · 숙소 · 항공편 결제 · 날짜 메모(note 일정) | ❌     | 파일 · 트리거 · 순서(position)가 얽혀 중간에 끊기면 안 된다 |     |
| 그 밖의 모든 저장                                            | ❌     | 오프라인이면 막는다                                         |     |

- 대기열 저장은 오프라인이면 멈췄다가(TanStack `networkMode: "online"`) 연결되면 올라간다. 대기열은 한 줄(`scope`)이라 같은 항목을 여러 번 바꿔도 누른 순서대로 올라간다
- 화면은 누르는 순간 바뀐다(낙관적). 지워졌거나 권한이 없어 실패하면 다시 해 보지 않고 그 항목만 되돌린 뒤 대기열에서 뺀다(`dropDeadEndFailures` — 다시 해도 같아서). 서버에 닿지 못해 실패하면(3번 다시 해 본 뒤, `retrySync`) 화면은 그대로 두고 「저장 실패 · 다시 시도」 로 남긴다
- 앱을 닫거나 새로고침해도 남는다 — 대기열은 TanStack 캐시와 따로 IndexedDB(`tripmate-sync` › `outbox`)에 저장 하나마다 한 줄로 쓰고, 줄마다 주인 탭을 적는다.
  TanStack 의 캐시 저장은 탭마다 캐시 전체를 한 칸에 통째로 써서, 같은 앱이 열린 다른 탭이 나중에 쓰면 이 탭의 대기열이 사라졌다(②-a 확인 중 발견)
- 탭은 살아 있는 동안 잠금(Web Locks `tm-sync-tab-{id}`)을 쥔다. 앱이 시작할 때 주인 탭이 닫힌 줄만 누른 순서대로 다시 올린다(`tm-sync-claim` 잠금으로 한 탭씩) — 살아 있는 다른 탭의 대기열은 건드리지 않는다
- 저장 함수는 키마다 `queryClient.setMutationDefaults` 로 앱이 시작할 때 등록한다(`registerChecklistSync` · `registerPackSync` · `registerMemoSync` · `registerExpenseSync`) — 기기에서 되살린 저장에는 함수가 없어서
- 새로 만드는 저장(메모 · 비용)은 **id 를 화면에서 만든다**(`crypto.randomUUID`, 창 하나에 하나 — 실패한 뒤 「저장」 을 다시 눌러도 같은 줄이다. 앞서 실패한 저장은 빼고 목록의 그 줄을 바꿔 끼운다, `dropFailedTwins`). 같은 저장이 두 번 올라가면 unique 위반(23505, `isDuplicateKey`)을 성공으로 본다. 비용은 지출 → 나눔 순서라, 나눔을 넣다 서버에 닿지 못하면 지출을 남겨 두고 다음에 나눔만 이어서 넣는다(`createExpenseOnce`)
- 창(메모 작성 · 비용 추가)은 **온라인이면 끝날 때까지 기다리고**(오류를 그 창에 보이게), **오프라인이면 바로 닫는다** — 화면에는 이미 들어갔고 대기열에 남았다. 체크처럼 창이 없는 동작은 늘 바로 반영한다
- 실시간 알림(`useRealtimeTrip`)으로 다시 읽는 것은 대기열이 올라가는 동안 미룬다(`createSyncDeferral`) — 내 첫 저장이 올라가 알림이 오면, 아직 올리지 않은 다음 변경이 화면에서 잠깐 사라진다. 미룬 키는 모아 두었다가 대기열이 비면 한 번에 다시 읽는다(버리면 다른 종류의 저장이 도는 동안 온 일행의 변경을 놓친다)
- 끝난 저장의 줄은 지운다. 서버에 닿지 못해 실패한 줄만 남긴다 — 그 탭에서는 「다시 시도」, 닫히면 다음에 열 때 다시 올린다

## 일행과 같은 항목을 고쳤을 때

**나중 수정 우선 + 알림**(시안대로, 2026-10-23 사용자 결정).

- 누를 때 본 항목의 버전(`updated_at`)을 함께 보낸다. 올릴 때 그 버전이면 그대로 고치고, 그사이 일행이 고쳤으면 내 것으로 덮고 「일행이 먼저 고친 항목을 내 수정으로 바꿨어요」(`updateLatestWins`)
- 덮는 것은 내가 바꾼 칸만이다(체크는 상태 · 챙김 칸, 메모는 본문 · ★ · 링크) — 일행이 고친 다른 칸(제목 등)은 그대로 남는다
- 지우기(메모)도 같다 — 그사이 일행이 고쳤어도 지우고 「일행이 먼저 고친 메모를 지웠어요」. 이미 지워졌으면 그대로 끝
- 오프라인에서 쓴 메모를 이어서 고치면, 고치는 저장은 화면에 먼저 보인 버전(쓴 때)을 들고 있다 — 쓰기가 올라가며 서버 버전을 기억해(`rememberOwnWrite`) 그것과 비교한다(이 탭에서만)
- 같은 항목을 오프라인에서 두 번 바꾸면 두 번째는 내가 만든 버전과 비교한다(이 탭에서만 기억). 새로고침 뒤에 이어 올린 것은 기억이 없어 내 수정을 일행 것으로 잘못 알릴 수 있다
- 그사이 지워졌으면 그 항목만 되돌린다

## 동기화 칩

`widgets/connection-status`. 대기열에 상태가 있을 때만 보인다 — 평소 온라인 저장마다 깜빡이지 않게.

| 칩                    | 언제                                                                       |
| --------------------- | -------------------------------------------------------------------------- |
| 변경 N건 대기         | 오프라인이라 멈춘 대기열 저장이 있다                                       |
| 저장 중…              | 기다리던 변경을 올리는 중(오프라인에서 쌓였거나 되살아난 것)               |
| 모두 저장됨           | 기다리던 변경이 다 올라간 순간, 2초                                        |
| 저장 실패 · 다시 시도 | 서버에 닿지 못해 실패한 대기열 저장이 있다. 누르면 같은 값으로 다시 올린다 |

- 오프라인이면 띠 오른쪽, 온라인이면 오른쪽 위 헤더 바로 아래에 뜬다. 일행의 수정을 덮었다는 알림은 칩 아래에 잠깐(화면 토스트와 겹치지 않게 위)

## 확인할 때

- 자동화 탭은 오프라인으로 바꿀 수 없다 — `navigator.onLine` 을 바꾸고 `offline` · `online` 이벤트를 보내 흉내 낸다
- TanStack 은 탭이 보이지 않으면(자동화 탭은 늘 백그라운드) 멈춘 저장을 잇지 않는다 — `document.visibilityState` 를 `visible` 로 바꾸고 `window` 에 `visibilitychange` 를 보낸다
- 같은 앱이 열린 다른 탭이 있으면 캐시 저장(`tripmate-query-cache`)을 덮는다 — 대기열은 따로 있어 상관없지만, 캐시를 볼 때는 다른 탭을 닫는다
- 「오프라인용으로 받기」 는 `pnpm build && pnpm start` 에서 본다. 서버를 끄면 화면을 받지 못해 일부 실패를, 끈 채로 안 열어 본 화면을 열면 받은 칸에서 나오는지를 본다. 새 버전 옮기기는 다시 빌드한 뒤 `registration.update()`
