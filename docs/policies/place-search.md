# 장소 검색 정책

일정에 담을 장소를 **어디서 · 어떻게 찾게 하는지** 모았다. 구글 지도 · 장소 API 를 쓰는 결정도 여기에 쌓는다.
권한 · 데이터 규칙은 [`data-model.md`](data-model.md), 의존성 결정은 [`../engineering/library-policy.md`](../engineering/library-policy.md) 에 있다.

## 장소를 찾는 곳

「일정 추가」 화면(모바일 전체 화면 · PC 480×700 모달, `features/schedule/add-schedule`)에서 세 곳을 쓴다.

| 곳             | 무엇                                                                                                                                                                                                                                              | 지금                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 추천 장소 탭   | 운영자가 고른 도시별 장소 목록(큐레이션)                                                                                                                                                                                                          | 큐레이션(#34) 전까지 **구글 검색 결과로 대신**한다. 검색어가 없으면 안내만                                    |
| 저장한 장소 탭 | 내가 만든 장소 중 이 여행 도시에 있는 것(보관함). 일정에서 뺀 장소도 남는다                                                                                                                                                                       | `places` (`created_by` = 나, `city_id` ∈ 여행 도시)                                                           |
| 직접 추가      | 장소 입력 폼을 두 단계로 연다 — ① 위치 선택(검색어는 위치 검색칸으로, 같은 도시 제한 검색 · 지도 중앙 핀 · 핀 위치 주소, **위치는 반드시 정한다**) → ② 장소 정보(이름은 고른 장소 이름으로 채움). 예약 상태 · 시간 · 메모는 담은 뒤 일정 상세에서 | `features/schedule/place-form` → `create_place_schedule`. 그날 끝에 담고 두 창을 모두 닫아 그날 일정을 보인다 |

- **직접 추가에서 이미 있는 장소를 고르면** 「이미 저장된 장소예요. 이 장소를 쓸까요?」를 묻는다. 「이 장소로 담기」는 그 장소를 그대로 붙이고(새 장소를 만들지 않는다), 「새로 등록할래요」는 그 구글 장소와의 연결을 끊고 같은 핀 위치에서 새 장소로 만든다. 이미 있는 장소 = 내가 만든 장소 또는 이 여행 일정이 쓰는 장소 중 같은 구글 장소(`findAttachablePlace`, 붙일 수 있는 범위인 `can_attach_place` 와 같다)
- 카테고리 칩은 **저장한 장소 탭에서만** 보인다. 구글 결과는 고르기 전에는 카테고리를 모른다
- 「일정에 있음」 배지는 여행 전체 일정 기준이다(날짜 무관). 장소 id, 구글 결과는 구글 장소 id 로 맞춘다
- 같은 구글 장소를 다시 담으면 장소는 하나, 일정이 둘이다(`add_schedule_place`)

## 구글 검색 범위 — 여행 도시로 제한한다

도쿄 여행에서 한국 · 다른 지역 결과가 섞이지 않게, 구글 장소 자동완성을 **제한**(restriction)한다. 먼저 보여 줄 뿐인 bias 가 아니다.

| 조건                  | 값                                                                                                                                   | 근거                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `includedRegionCodes` | 고른 도시의 나라(`cities.country_code`)                                                                                              | 다른 나라 결과를 아예 뺀다                                                                                                                                                                                    |
| `locationRestriction` | 고른 도시 중심 사각형. 반폭은 도시 지도 줌(`cities.zoom`)으로 — 줌 11 이상 **±1°**(약 100km), 줌 10 ±2°, 줌 9 이하는 **걸지 않는다** | 도쿄면 하코네(약 80km)까지 들어오고 오사카는 빠진다. 나라 · 섬 무리 단위(하와이 · 오키나와 · 미얀마 · 「국내 어디론가」)는 ±몇 도로는 포함 지역이 빠져서, 사각형 대신 중심 쪽을 먼저 보이는 bias(50km)만 건다 |

둘을 함께 걸면 둘 다 만족하는 결과만 온다. 계산은 `shared/lib/google-places/search-area.ts` 의 `searchArea` 한 곳이고(일정 추가 · 장소 입력 폼이 같이 쓴다), 범위는 `searchHalfSpan` 에서 조정한다.

**여러 도시 여행** — 검색창 아래 도시 칩(`[도쿄] [오사카]`)으로 한 도시를 고른다. 사각형 하나로 여러 도시를 덮으면 그 사이 지역(나고야 · 시즈오카 …)이 섞이기 때문이다.
구글 자동완성은 요청 하나에 사각형 하나만 받는다. 도시마다 따로 요청해 합치는 방법은 요청 수만큼 비용이 늘어 택하지 않았다.

- 처음 고르는 도시: 담으려는 날의 첫 장소에서 가장 가까운 여행 도시, 그날 장소가 없으면 첫 도시(`defaultCityId`)
- 도시가 하나인 여행은 칩을 숨긴다
- **도시가 없는 여행**(0006 이전)은 제한 없이 찾는다
- **범위 밖 장소**(예: 도쿄 여행 중 닛코 당일치기, 약 120km)는 검색에 나오지 않는다. 여행에 그 도시를 추가하거나 직접 추가로 담는다
- **알려진 한계 — 도시 카드의 근교가 잘릴 수 있다**(#76). 사각형은 도시 중심만으로 정해서, `cities.areas` 에 적힌 근교가 밖일 때가 있다(후쿠오카 → 벳푸, 삿포로 → 하코다테, 빈 → 잘츠부르크 …).
  지역 좌표가 시드에 없어서 사각형을 지역에 맞출 수 없다. 사각형을 없애고 나라 + bias 로 가면 이 문제는 사라지지만 「도쿄 여행엔 도쿄 지역만」이 깨져 택하지 않았다. 지역 좌표를 넣으면(#37) 사각형을 지역에 맞춘다

## 주소 — 핀 위치에서 불러온다

장소 입력 ① 에서 지도가 멈추면(450ms) 핀 위치를 역지오코딩해 주소를 **로마자 → 현지어 → 한글** 순으로 함께 적는다(`shared/lib/google-places/use-reverse-geocode.ts`, 2026-10-05 사용자 결정).

| 칸                      | 무엇                                             | 예(시부야)                          |
| ----------------------- | ------------------------------------------------ | ----------------------------------- |
| `places.address`        | 한국어로 요청한 번지 주소 — 일본은 로마자로 온다 | 1-chōme-22-7 Jinnan, Shibuya, Tokyo |
| `places.address_local`  | 현지어 주소 — 현지인 · 택시에 보여 줄 용도       | 東京都渋谷区神南１丁目２２−７       |
| `places.address_ko`     | 한글 — 같은 응답의 한글 동네 이름 + 번지 숫자    | 도쿄도 시부야구 진난 1 조메 22-7    |
| `places.address_detail` | 사용자가 적는 상세 위치                          | 파르코 본관 8F                      |

- **일본 번지는 구글에 한국어 표기가 없다.** 한국어로 요청해도 번지 결과는 로마자로 오고, 동네 단위(sublocality) 결과만 한글로 온다. 그래서 한글 줄은 한글 동네 이름 뒤에 번지 결과에만 있는 숫자를 붙여 만든다(`koreanAddress`). 한글 결과가 구 · 시 단위뿐이면 숫자를 붙이지 않는다. 추가 호출은 없다
- 시안의 「한국어 주소」(OpenStreetMap)는 서비스용 공개 서버의 사용 제한 · 새 외부 의존 때문에 택하지 않았다(2026-10-04 사용자 결정)
- 현지어는 도시의 나라 코드로 정한다(`localLanguage` — 일본 ja, 베트남 vi …). 한국은 한국어가 곧 현지어라 한 줄만, 목록 밖 나라(벨기에처럼 언어가 갈리는 곳)는 현지어 줄이 없다
- 나라 이름 · 우편번호 · 「〒」 는 뺀다. 결과 중 번지(street_address · premise)를 먼저 고른다 — 첫 결과는 근처 가게일 때가 많다
- 주소를 못 불러와도(키 권한 · 네트워크) 다음 단계로 갈 수 있다. 주소 없이 저장된다

## 위치만 고르기 — 숙소 주소

숙소 입력의 「주소」 칸은 장소 입력 폼의 ① 위치 선택만 연다(`PlaceFormDialog mode="location"`, #88). 검색 · 지역 제한 · 지도 핀 · 역지오코딩 주소는 그대로이고, 「이 위치로 선택」 이 ② 로 가는 대신 고른 위치(`PickedLocation` — 좌표 · 구글 장소 · 이름 · 주소 세 줄 · 구글맵 링크)를 돌려준다. 이미 있는 장소인지는 묻지 않는다 — 장소는 받는 쪽(`save_stay`)이 내 구글 장소를 다시 쓰거나 새로 만든다.

- 구글맵 링크: 구글 장소를 골랐으면 그 장소 링크(`googleMapsUrl`), 지도를 끌어 정했으면 좌표 검색 링크(`coordsMapsUrl`). 입력칸은 없다
- 도시(검색 범위 · 지도 중심)는 여행의 첫 도시

## 비용

구글 장소 API 는 호출마다 과금된다. 무료 한도 안에서 쓰는 방안은 #35 에서 정한다.

- **세션 토큰**: 검색 여러 번 + 고르기(상세 조회) 1번이 세션 1회로 묶인다. 고르면 세션이 끝나고 다음 입력부터 새 세션이다
- 한 검색에서 **여러 곳을 고르면** 두 번째부터는 토큰 없이 장소 id 로 상세를 조회한다(따로 과금). **끝난 세션의 토큰을 다시 쓰면 그 세션이 무효가 되어 앞선 자동완성 요청까지 토큰 없이 과금된다**(구글 문서 <https://developers.google.com/maps/documentation/javascript/place-autocomplete-data>, 2026-10-04 확인). 그래서 같은 결과 목록의 토큰을 두 번 쓰지 않는다(`shared/lib/google-places/use-place-suggestions.ts`). 무료 한도 관리는 #35
- 상세 조회 필드는 `id · displayName · location · formattedAddress · primaryType · types` 만 받는다(필드가 많을수록 비싸다). 이름(`displayName`)이 Place Details Pro 등급이라 같은 등급의 `primaryType`, 더 낮은 `types` 는 값이 그대로다(구글 문서 <https://developers.google.com/maps/documentation/javascript/place-class-data-fields>, 2026-10-05 확인). 운영시간 · 웹사이트 · 별점은 Enterprise 등급이라 받지 않는다
- **장소 입력 ② 자동 채움** — 위치 검색으로 구글 장소를 고르면 이름 · 카테고리(구글 장소 종류 → 우리 카테고리, `categoryFromGoogle`) · 구글맵 링크를 채운다. 구글맵 링크는 장소 id 로 지도 URL 을 직접 만든다(호출 · 과금 없음, 장소 id 는 저장 가능). 칸이 비었거나 화면이 채운 값 그대로일 때만 바꾸고, 지도를 끌어 구글 장소 연결이 끊기면 자동으로 채운 링크는 지운다(`lib/google-autofill.ts`)
- 저장하는 것은 이름 · 좌표 · 주소 · 구글 장소 id 뿐이다. **구글 평점 · 리뷰 수는 약관상 저장할 수 없다** — 별점은 사용자가 직접 적는다(#34)
- 일정 카드의 거리 · 시간은 Routes API 대신 직선거리로 계산한다(결정 기록: `library-policy.md`)
- **역지오코딩**: 지도가 멈출 때마다 최대 2회(한국어 · 현지어). 끌기 · 확대 중에는 묻지 않고, 같은 좌표(약 10cm 안)는 다시 묻지 않는다. 한국 · 목록 밖 나라는 1회
- **주소 검색(지오코딩)**: 장소 입력 ① 의 위치 검색은 장소 자동완성과 함께 주소로도 한 번 묻는다(입력이 500ms 멈출 때 1회, `use-address-search.ts`). 장소 자동완성은 가게를 먼저 주고 한국어로 적은 일본 주소(「시부야구 진난 1-22-7」)의 번지를 거의 주지 않아서다. 나라로 제한 · 그 나라 기준으로 읽고(region) · 검색 사각형을 먼저 보고(bounds), 사각형 밖 결과는 버린다

## 담기

- 고른 곳은 하단 트레이에 고른 순서대로 모이고, 「day N에 K곳 추가」로 **한 번에** 담는다(`add_schedule_places`). 하나라도 실패하면 아무것도 남지 않는다
- 담을 날은 화면 머리의 「day N · 날짜에 추가 ⌄」로 바꾼다
- 실패 문구는 원인별이다 — 도시 · 위치 없음, 이름 없음, 권한은 해결 방법을, 나머지는 다시 시도를 안내한다(`addPlaceErrorMessage`)
