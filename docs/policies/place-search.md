# 장소 검색 정책

일정에 담을 장소를 **어디서 · 어떻게 찾게 하는지** 모았다. 구글 지도 · 장소 API 를 쓰는 결정도 여기에 쌓는다.
권한 · 데이터 규칙은 [`data-model.md`](data-model.md), 의존성 결정은 [`../engineering/library-policy.md`](../engineering/library-policy.md) 에 있다.

## 장소를 찾는 곳

「일정 추가」 화면(모바일 전체 화면 · PC 480×700 모달, `features/schedule/add-schedule`)에서 세 곳을 쓴다.

| 곳              | 무엇                                                                        | 지금                                                                       |
| --------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 추천 장소 탭    | 운영자가 고른 도시별 장소 목록(큐레이션)                                    | 큐레이션(#34) 전까지 **구글 검색 결과로 대신**한다. 검색어가 없으면 안내만 |
| 저장한 장소 탭  | 내가 만든 장소 중 이 여행 도시에 있는 것(보관함). 일정에서 뺀 장소도 남는다 | `places` (`created_by` = 나, `city_id` ∈ 여행 도시)                        |
| 이름만으로 추가 | 검색어를 이름으로 담는다. 위치가 없어 지도에 표시되지 않는다                | ②-b 에서 「직접 추가」(장소 입력 폼, 지도 핀)로 바뀐다                     |

- 카테고리 칩은 **저장한 장소 탭에서만** 보인다. 구글 결과는 고르기 전에는 카테고리를 모른다
- 「일정에 있음」 배지는 여행 전체 일정 기준이다(날짜 무관). 장소 id, 구글 결과는 구글 장소 id 로 맞춘다
- 같은 구글 장소를 다시 담으면 장소는 하나, 일정이 둘이다(`add_schedule_place`)

## 구글 검색 범위 — 여행 도시로 제한한다

도쿄 여행에서 한국 · 다른 지역 결과가 섞이지 않게, 구글 장소 자동완성을 **제한**(restriction)한다. 먼저 보여 줄 뿐인 bias 가 아니다.

| 조건                  | 값                                                                                                                                   | 근거                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `includedRegionCodes` | 고른 도시의 나라(`cities.country_code`)                                                                                              | 다른 나라 결과를 아예 뺀다                                                                                                                                                                                    |
| `locationRestriction` | 고른 도시 중심 사각형. 반폭은 도시 지도 줌(`cities.zoom`)으로 — 줌 11 이상 **±1°**(약 100km), 줌 10 ±2°, 줌 9 이하는 **걸지 않는다** | 도쿄면 하코네(약 80km)까지 들어오고 오사카는 빠진다. 나라 · 섬 무리 단위(하와이 · 오키나와 · 미얀마 · 「국내 어디론가」)는 ±몇 도로는 포함 지역이 빠져서, 사각형 대신 중심 쪽을 먼저 보이는 bias(50km)만 건다 |

둘을 함께 걸면 둘 다 만족하는 결과만 온다. 계산은 `features/schedule/add-schedule/lib/search-area.ts` 의 `searchArea` 한 곳이고, 범위는 `searchHalfSpan` 에서 조정한다.

**여러 도시 여행** — 검색창 아래 도시 칩(`[도쿄] [오사카]`)으로 한 도시를 고른다. 사각형 하나로 여러 도시를 덮으면 그 사이 지역(나고야 · 시즈오카 …)이 섞이기 때문이다.
구글 자동완성은 요청 하나에 사각형 하나만 받는다. 도시마다 따로 요청해 합치는 방법은 요청 수만큼 비용이 늘어 택하지 않았다.

- 처음 고르는 도시: 담으려는 날의 첫 장소에서 가장 가까운 여행 도시, 그날 장소가 없으면 첫 도시(`defaultCityId`)
- 도시가 하나인 여행은 칩을 숨긴다
- **도시가 없는 여행**(0006 이전)은 제한 없이 찾는다
- **범위 밖 장소**(예: 도쿄 여행 중 닛코 당일치기, 약 120km)는 검색에 나오지 않는다. 여행에 그 도시를 추가하거나 이름만으로 담는다

## 비용

구글 장소 API 는 호출마다 과금된다. 무료 한도 안에서 쓰는 방안은 #35 에서 정한다.

- **세션 토큰**: 검색 여러 번 + 고르기(상세 조회) 1번이 세션 1회로 묶인다. 고르면 세션이 끝나고 다음 입력부터 새 세션이다
- 한 검색에서 **여러 곳을 고르면** 두 번째 상세 조회부터는 따로 과금된다(세션이 이미 끝났다). 일정 추가 화면은 여러 곳 고르기를 허용하므로 감수한다
- 상세 조회 필드는 `id · displayName · location · formattedAddress` 만 받는다(필드가 많을수록 비싸다)
- 저장하는 것은 이름 · 좌표 · 주소 · 구글 장소 id 뿐이다. **구글 평점 · 리뷰 수는 약관상 저장할 수 없다** — 별점은 사용자가 직접 적는다(#34)
- 일정 카드의 거리 · 시간은 Routes API 대신 직선거리로 계산한다(결정 기록: `library-policy.md`)

## 담기

- 고른 곳은 하단 트레이에 고른 순서대로 모이고, 「day N에 K곳 추가」로 **한 번에** 담는다(`add_schedule_places`). 하나라도 실패하면 아무것도 남지 않는다
- 담을 날은 화면 머리의 「day N · 날짜에 추가 ⌄」로 바꾼다
- 실패 문구는 원인별이다 — 도시 · 위치 없음, 이름 없음, 권한은 해결 방법을, 나머지는 다시 시도를 안내한다(`addPlaceErrorMessage`)
